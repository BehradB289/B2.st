# راهنمای استقرار و کانتینرسازی موتور بازی Mario HTML5 (B2.st Studio)

این سند مراحل استقرار، پیکربندی امنیتی، و معماری اجرای کانتینر بازی ماریو در استودیو **B2.st** را تشریح می‌کند.

---

## ۱. معماری و ویژگی‌های کانتینرسازی

- **بیلد چندمرحله‌ای (Multi-Stage):**
  - **مرحله ۱ (`test-runner`):** اجرای خودکار تست‌های واحد فیزیک، گرانش و تداخل AABB در محیط Node.js قبل از ایجاد لایه وب.
  - **مرحله ۲ (`production`):** استقرار مبتنی بر `nginx:alpine` با حداقل حجم (کمتر از ۲۵ مگابایت) و بدون ابزارهای سیستمی اضافی.
- **امنیت سطح بالا (Hardened & Rootless):**
  - اجرای وب‌سرور تحت کاربر غیر ریشه `nginx` (UID 101).
  - فایل‌سیستم اصلی کانتینر به صورت فقط‌خواندنی (`read_only: true`).
  - نگاشت دیرکتوری‌های پویای Nginx در دیسک موقت RAM (`tmpfs`).
  - جلوگیری از ترفیع دسترسی با `no-new-privileges:true`.
  - تنظیم هدرهای امنیتی مدرن مطابق استانداردهای OWASP (CSP, HSTS-ready, X-Frame-Options).
- **عملکرد و کارایی:**
  - فعال‌سازی فشرده‌سازی خودکار Gzip برای تمام فایل‌های `.js`, `.json`, `.css` و `.svg`.
  - سیستم کش مرورگر برای است‌های استاتیک (`Cache-Control: immutable, max-age=7d`).
  - غیرفعال‌سازی کش برای فایل شل `index.html` جهت دریافت آنی آپدیت‌ها.
  - مانیتورینگ سلامت پیوسته با اندپوینت `/healthz`.

---

## ۲. پیش‌نیازهای سرور

- سیستم‌عامل: Ubuntu 22.04 LTS / Debian 12 / AlmaLinux 9
- پکیج‌های نصب‌شده: `docker engine` (نسخه 24+) و پلاگین `docker compose` (نسخه v2+)
- ابزار ارتباطی `curl`

---

## ۳. مراحل راه‌اندازی سریع (Quick Start)

### گام اول: کلون مخزن و تنظیم متغیرهای محیطی
```bash
git clone https://github.com/b2st/mario-html5.git
cd mario-html5

# کپی متغیرهای پیش‌فرض
cp .env.example .env
```

در صورت نیاز به تغییر پورت خارجی سرور، مقدار `HOST_PORT` را درون `.env` تغییر دهید (پیش‌فرض: `80`).

### گام دوم: استقرار خودکار با اسکریپت Production
اسکریپت زیر به صورت خودکار تست‌ها را اعتبارسنجی کرده، ایمیج را کامپایل کرده و کانتینر را بدون داون‌تایم مستقر می‌کند:

```bash
chmod +x scripts/deploy.sh scripts/rollback.sh
./scripts/deploy.sh
```

---

## ۴. محیط توسعه محلی (Hot Reloading)

برای توسعه‌دهندگان، فایل اختصاصی `docker-compose.dev.yml` تهیه شده است که کدهای `src/` و `public/` را به صورت زنده بدون نیاز به بیلد مکرر در کانتینر قرار می‌دهد:

```bash
docker compose -f docker-compose.yml -f docker-compose.dev.yml up
```
سپس از طریق مرورگر به آدرس `http://localhost:8080` دسترسی خواهید داشت.

---

## ۵. تست و اعتبارسنجی دستی

بررسی وضعیت سلامت کانتینر مستقر:
```bash
curl -I http://localhost/healthz
# پاسخ مورد انتظار: HTTP/1.1 200 OK
```

مشاهده لاگ‌های زنده در قالب JSON:
```bash
docker compose logs -f mario-game
```

---

## ۶. عملیات بازگردانی اضطراری (Rollback)

در صورت بروز هرگونه ناسازگاری پس از استقرار:
```bash
./scripts/rollback.sh
```
این اسکریپت فوراً ایمیج پیشین را جایگزین می‌کند.
